# 02 · 架构与技术选型

> 状态：✅ v4（M5 补导出门禁与 `slow.py` 落点）｜数值口径唯一真相源见 `data/README.md` §四
> 本文只写"结构"，不写会漂移的实现数字。

## 一、分层

```
┌──────────────────────────────────────────────────────────────┐
│ 入口层   cli.py（argparse 参数面）→ main() 返回退出码          │
│          tui/（Textual App，唯一界面形态）                     │
├──────────────────────────────────────────────────────────────┤
│ 编排层   ingest.py（扫描→解析→落库）  export.py（模型→md/json） │
│          queries.py（只读 SQL，供 TUI/导出共用）                │
├──────────────────────────────────────────────────────────────┤
│ 判定层   flaky.py（分型）  slow.py（分位数/回归）  diff.py（run diff）│
│          ——纯函数，输入是内存记录，不碰 IO、不读时钟             │
├──────────────────────────────────────────────────────────────┤
│ 表示层   model.py（四态/耗时） identity.py（身份键）            │
│          report_model.py（字段声明顺序 = md 列序 = JSON 键序）   │
├──────────────────────────────────────────────────────────────┤
│ 基础层   db.py（schema/连接）  paths.py（路径与 XDG）           │
│          rules.py（规则包加载）  keys.py（键位单点）             │
│          exit_codes.py（退出码单点）                            │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向单向向下**：判定层不得 import 入口层或 Textual；`queries.py` 不得 import
`tui/`；`report_model.py` 不得 import Textual（TUI 与 export 都是它的渲染器）。

**可证伪守门**（M3 起）：`tests/test_no_network.py` 用 AST 扫描 `src/`，禁止
`socket` / `urllib` / `http` / `requests` / `httpx` / `aiohttp` 的导入，以及**可静态判定**的
动态导入（`importlib.import_module("requests")` / `__import__("socket")`）；
`tests/test_layering.py` 用 AST 断言上述依赖方向。

两条守门**各由两半组成**，缺一半就等于没守：

| 守门 | 第 1 半（不许） | 第 2 半（必须） | 变异验证 |
| --- | --- | --- | --- |
| 零网络 | `cli.FORBIDDEN_NETWORK_MODULES` | `cli.ALLOWED_THIRD_PARTY` 白名单（拦"动态导入一个未登记依赖"） | 临时副本注入 `import socket` / `import_module('requests')` → 必红 |
| 分层 | `cli.LAYER_RULES`（判定/表示/查询层不得 import 入口层、`tui/`、Textual、DB） | `cli.REQUIRED_IMPORTS`（`app.py` **必须** import `report_model`；`queries.py` **必须** import `model`） | 删掉 `app.py` 里对 `report_model` 的引用 → 必红 |

第 2 半不是装饰：把 `app.py` 里对共用模型的引用删掉，界面照样能跑，但
"md 字段与 TUI 一致"（§五 的决策）就悄悄失效了——只有"必须 import"这条能拦住它。

**守门的边界（如实写）**：静态扫描覆盖的是 import 面。刻意拼串绕过
（`getattr(__import__("test"+"deck"))`）拦不住；那层的兜底是白名单 + 人工评审，
本守门不假装覆盖它。

## 二、CLI 契约

唯一入口 `testdeck`（`[project.scripts]` → `testdeck.cli:main`）。

| 命令 | 参数 | 输出 | 退出码 |
| --- | --- | --- | --- |
| `testdeck ingest <paths...>` | `--db PATH`、`--glob PATTERN`（可重复，默认 `**/junit*.xml`）、`--dry-run` | ingest 摘要（文件数 / run 数 / 用例数 / skipped 分组）到 stdout；库写入 SQLite | 0 / 2 / 3 |
| `testdeck tui` | `--db PATH`、`--run RUN_ID` | 三栏 TUI；`F`/`S`/`D` 切视图 | 0 / 2 / 3 |
| `testdeck export` | `--format {md,json}`、`--db PATH`、`--run RUN_ID`、`--fail-on {flaky,new-failures,regressions}` | md 表格或 JSON 到 stdout | 0 / 1 / 2 / 3 |

**`export` 的退出码细则（M5 实装口径）**：`--fail-on` 命中 → **1**（`flaky`：分型 flaky 数 >0；`new-failures`：相对 base run 新增失败数 >0；`regressions`：回归清单非空）；未命中 → 0；未知 `--format` / `--fail-on` → argparse `choices` 拦下（2）；库不存在 / 库存在但无 run / `--run` 不存在 → **3**。**门禁判定只读模型**（`report_model.gate_hits`），不重新查库——保证"CI 拦下来的"就是"屏幕上看到的"。
| `testdeck selftest` | — | 单点定义自检（键位/退出码/规则包/零网络/分层） | 0 / 1 |

**`tui` 的退出码细则（M3 实装口径）**：库文件不存在 / 库存在但没有 run /
`--run` 指向不存在的 run → **一律 exit 3**（依赖缺失），stderr 点名路径并提示
"先跑 `testdeck ingest`"；`--db ""` 仍是用法错误（exit 2）。**空库不等于"没有失败"**，
所以它不给 0。

**参数语义三条**（写进测试，不靠约定）：

1. **不用 `or DEFAULT`**：`--db ""` 是用法错误（exit 2），不得静默回落到默认库；
   `--run ""` 同理。
2. **按 `format` 分派，未知格式显式拒绝**：`--format` 用 `choices`，argparse 直接 exit 2。
3. **中间产物全落显式路径**：`ingest` 只写 `--db` 指向的库；不写任何隐藏缓存文件。
   `--dry-run` 前后全仓快照差集必须为空（失败路径零副作用）。

**退出码语义**（`src/testdeck/exit_codes.py` 单点，见 `plan/05` §二）：
`0` 达标 / `1` 门禁触发 / `2` 用法错误 / `3` 依赖缺失或库不可读。
`4`（`NOT_READY`）**只在 M0 存在**：`ingest`/`tui`/`export` 尚未实现时返回 4；
M2 起逐命令退役（`ingest` 于 M2、`tui` 于 M3、**`export` 于 M5**），退役表在 `plan/05` §二。
**M5 起 `cli.py` 里已无返回 4 的分支**（判据见 `tests/test_exit_codes.py`）。
**常量保留**——退役不是删常量（历史留档要能读）。

**库的两种打开方式**（M3 区分，别混用）：

| 函数 | 语义 | 用在哪 |
| --- | --- | --- |
| `db.connect(path)` | "确保 schema"：建目录、建表、写 `meta` 版本；版本不符 → `DbError` | `ingest` 的写侧 |
| `db.open_existing(path)` | "库得先在那儿"：**不建目录、不建表、不写 meta**；不存在/无 schema 登记/版本不符 → `DbError` | `tui` 与 M5 的 `export` 的读侧 |

读侧用 `connect` 是错的：它会把"库不存在"悄悄变成"建一个空库"，于是
"库不存在 → exit 3"这条降级判据永远走不到（空库还会被误读成"没有失败"）。

## 三、数据库

**位置**：`$XDG_DATA_HOME/testdeck/testdeck.db`，未设置时 `~/.local/share/testdeck/testdeck.db`
（Windows 回落 `%USERPROFILE%\.local\share\testdeck\`）；`--db` 覆盖，且**覆盖值必须回显**
在 ingest 摘要与 export 输出里（避免"写到了别处却不知道"）。

**四张表**（DDL 在 `db.py`；M0 落 schema 常量与建库函数，M2 落四表 upsert）：

```sql
CREATE TABLE runs (
  run_id      INTEGER PRIMARY KEY,
  branch      TEXT NOT NULL,
  commit_sha  TEXT NOT NULL,
  ci_run_id   TEXT NOT NULL,
  started_at  TEXT NOT NULL,
  source_path TEXT NOT NULL,
  framework   TEXT NOT NULL,
  ingested_at TEXT NOT NULL,
  UNIQUE (branch, commit_sha, ci_run_id)
);

CREATE TABLE suites (
  suite_id    INTEGER PRIMARY KEY,
  run_id      INTEGER NOT NULL REFERENCES runs(run_id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  tests       INTEGER NOT NULL,
  failures    INTEGER NOT NULL,
  errors      INTEGER NOT NULL,
  skipped     INTEGER NOT NULL,
  time_ms     INTEGER,            -- 可空：没声明耗时就是 NULL，不是 0（M2 起）
  source_path TEXT NOT NULL,
  UNIQUE (run_id, name, source_path)
);

CREATE TABLE cases (
  case_id    INTEGER PRIMARY KEY,
  suite_name TEXT NOT NULL,
  classname  TEXT NOT NULL,
  name       TEXT NOT NULL,
  UNIQUE (suite_name, classname, name)
);

CREATE TABLE occurrences (
  run_id          INTEGER NOT NULL REFERENCES runs(run_id) ON DELETE CASCADE,
  case_id         INTEGER NOT NULL REFERENCES cases(case_id) ON DELETE CASCADE,
  status          TEXT NOT NULL CHECK (status IN ('pass','fail','skip','missing')),
  time_ms         INTEGER,
  failure_message TEXT,
  failure_type    TEXT,
  stack_first_line TEXT,
  PRIMARY KEY (run_id, case_id)
);
```

**schema 版本**：`db.SCHEMA_VERSION = 2`（M2 把 `suites.time_ms` 由 `NOT NULL
DEFAULT 0` 改为可空——"没声明耗时"与"耗时 0"是两件事）。连接时若发现已存在的库
版本不同，**直接给 `DbError`（退出码 3）并提示删库重建**，不静默复用：旧 DDL 的
`NOT NULL` 约束会让"缺失耗时"晚一点才炸。

**幂等与 NULL**：唯一键列全部 `NOT NULL`；未知值写**有值空串**而不是 NULL
（NULL 在唯一索引里彼此不等，会绕过 upsert）。`framework` 未知写 `"unknown"`。
`ci_run_id` 是 TEXT（不同 CI 的 id 形态不一，避免整数溢出/前导零丢失）。

**run 身份**：`(branch, commit_sha, ci_run_id)`，四个字段都**只从 XML 声明的元数据**里
读（根 / `<testsuite>` 上的 `branch` / `commit[_sha]` / `ci_run_id` / `timestamp` 属性）；
读不到写空串并计入摘要的 `degraded` 计数，**不猜时间、不拿路径凑身份**。
由此的必然结果：**没声明身份的产物全部落进同一个"未标注 run"（三元组全空串）**，
`runs.framework` 记该 run 覆盖到的框架集合（字典序逗号连接），`runs.source_path`
记该 run 按相对路径字典序的**首个**产物文件。要让多份产物分成多个 run，就让 CI
在 XML 里写身份属性（口径编号 K26，见 `plan/HANDOFF-M3.md` §3）。

## 四、构建与打包

- `pyproject.toml`：setuptools，`package-dir = {"" = "src"}`，`where = ["src"]`。
- 依赖：`textual>=1.0,<9`（运行时唯一第三方）；`dev` extra = `pytest>=7,<9`。
  本机实测：`textual 8.2.8` 要求 `>=3.9`，与 `requires-python = ">=3.9"` 一致。
- **规则包必须进包**：`src/testdeck/rules/*.json` 以 package-data 随 wheel/sdist 安装
  （`[tool.setuptools.package-data] testdeck = ["rules/*.json"]`）。**不放在仓库 `data/`**——
  否则装好的 CLI 读不到规则（"源码态能跑、装好就炸"）。`data/` 只放台账与语料生成器。
- `MANIFEST.in`：白名单覆盖 `src/testdeck/rules/*.json`（sdist 自足）。
- 版本号单点：`src/testdeck/__init__.py:__version__`，`pyproject` 用
  `dynamic = ["version"]` + `[tool.setuptools.dynamic] version = {attr = "testdeck.__version__"}`。
- 构建校验：`python -m build` 后 `twine check`（M6）；CI 只跑 `pip install -e ".[dev]"` 冒烟。

## 五、关键设计决策（M0）

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 规则包位置 | `src/testdeck/rules/`（包内） | 装好的 CLI 必须能读到；放 `data/` 会在安装面静默缺失 |
| 版本号 | 单点在 `__init__.py` | 三处写死版本号必然漂移 |
| TUI 与 export | 共用 `report_model.py` | 题面要求"md 字段与 TUI 完全一致"，共用模型是唯一可证伪的做法 |
| 查询与渲染 | `queries.py` 只读 SQL | 便于无头测试 summary 计数（Pilot 之外的第二条通路） |
| 导出与门禁 | `report_model.render_md/json` 只消费 `build_report` 的 dict；`gate_hits` 只读它 | 同一份模型 → 导出的字段与 TUI 必然一致；门禁结论与屏幕同源 |
| 大文件解析 | `iterparse` + 逐元素 `clear()` | 50MB+ 单文件不能整树 `parse` |
| 框架识别 | 根节点属性 + 文件名，失败记 `unknown` | "猜"会污染统计，第三态更诚实 |
| 时间 | 不读系统时钟（除 `ingested_at`） | 判定与导出必须可重放 |
