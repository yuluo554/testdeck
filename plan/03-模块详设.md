> 口径唯一来源：`data/README.md` §四

## 模块①：载入与归一化

**输入**：显式文件 / 目录 / glob（三种形态都收）；`--glob`（默认
`**/junit*.xml`、`**/surefire-reports/*.xml`、`**/build/test-results/**/*.xml`，
可重复；给定时**替换**默认值）；`gh run download` 落盘目录（只当普通目录读，**不调用 gh**）。

**实现要点**：

- `ingest.py:discover(paths, globs)` → 排序后的产物清单（路径统一正斜杠，相对扫描根；
  跨盘符回落绝对路径——`os.path.relpath` 会抛 `ValueError`）。
  排序固定：按**展示用相对路径**字典序，保证两次 ingest 的文件顺序一致。
  重复命中同一文件按 `normcase(abspath)` 去重；入参不存在 → 用法错误（exit 2），
  **一个都不写库**。
- `junit.py:parse_file(path)` 用 `iterparse(events=("start","end"))`：
  - `testcase` 与 `testsuite` 的 `end` 事件处都 `clear()`（5 万用例/50MB 级不进内存）；
  - 兼容 `<testsuites>` 包裹与裸 `<testsuite>` 根；带命名空间的标签按 localname 处理；
  - `failure` / `error` / `skipped` 子元素：`status` 分别映射 `fail` / `fail` / `skip`，
    `failure_type` 取 `type` 属性（缺省空串），`failure_message` 取 `message`，
    `stack_first_line` 取 `text` 的第一行（去首尾空白，空则空串）；
  - 元素重数按**标签分桶**（`failure`→failures、`error`→errors、`skipped`→skipped）：
    四态把 failure/error 合并成 `fail`，但计数必须分开，否则与框架声明值对不上；
  - 耗时：`time` 属性（十进制秒）→ 整数毫秒，**ROUND_HALF_UP**，实现在 `model.py`
    （`Decimal`，不用 `round()`——银行家舍入会在 .5 边界给出不同答案）；缺失写 `None`。
  - 解析失败（XML 坏、编码坏、缺根、不可读）→ 该文件计入 `skipped`，原因码
    `bad_xml` / `bad_encoding` / `no_testsuite` / `unreadable`，**不静默、不中断整批**；
    分类顺序：字节层（坏编码/不可读）→ 缺根（空文件/非 XML 文本）→ 坏结构。
  - **降级计数**（文件照常入库，只是某一项按缺失处理）：`bad_time`（耗时非法 → 记
    `None`）、`missing_name`（`testcase` 无 `name` → 该用例不落库，但**仍计入元素重数**）、
    `started_at_missing`、`bad_commit`（非 40 位十六进制 → 记空串）。
- 框架识别 `framework.py`：按 `<testsuite>`/根 `name` 属性 → `<properties>` 键名
  （`go.version`）→ 文件名的顺序判定 `pytest` / `gotestsum` / `playwright`；判定不出写
  `"unknown"`。**实测**：Playwright 的 suite name 是测试文件名、gotestsum 的是包名，
  两者都只能靠文件名/属性认出——不要用同一套假设。
- 身份键：`identity.py`。`suite_name` 取 `testsuite@name`；`classname` 取
  `testcase@classname`（缺省空串）；`name` 取 `testcase@name`（参数化用例保留完整参数串，
  不做任何截断或归一）。**run 身份**只从 XML 声明值读（K26）：
  `branch` / `commit[_sha]` / `ci_run_id` / `timestamp`；缺失写空串——没声明身份的
  产物因此归入同一个"未标注 run"（三元组全空串），`runs.framework` 记该 run 的框架集合。

**落库**：`db.py:upsert_run / upsert_suite / upsert_case / upsert_occurrence`，全部
`INSERT ... ON CONFLICT DO UPDATE`（用例身份用 `DO NOTHING`）。重复导入同一
`(branch, commit_sha, ci_run_id)` 只更新，不新增 run；`occurrences` 按
`(run_id, case_id)` 覆盖。整批落在**一个事务**里：要么全落，要么什么都不落。
同一文件内**重名 suite** 先合并计数再落库（不同文件名同但 `source_path` 不同 → 各留一行）。

**输出**：ingest 摘要（stdout，机读行 + 人读行）：

```
ingest: files=12 runs=3 cases=118 occurrences=354 skipped=1 framework=pytest,playwright,unknown
skipped: bad_xml=1 (bench/fixtures/pytest/broken.xml)
degraded: bad_time=2 (bench/fixtures/pytest/junit.xml)
db: C:/.../testdeck.db          ← 回显 --db 覆盖值
dry-run: 未写库（零副作用）      ← 仅 --dry-run 时出现
```

- 第一行的字段与顺序是**契约**（`tests/test_ingest.py` 逐字断言）；
  `runs` = 成功的 run 数，`cases` = 不同用例身份数，`occurrences` = 不同 `(run, case)` 对数，
  `skipped` = 未能解析的文件数，`framework` = 已解析文件的框架集合（字典序）。
- `skipped:` / `degraded:` 每个原因一行、按**单点顺序**输出；`files=0` 时多一行 note。

**降级**：`--db` 指向不可写目录 / 旧 schema 版本 → exit 3（依赖/环境不可用），
**整批不落库**；入参不存在 → exit 2；`--from-gh` 语义**未启用**（不在 CLI 契约里，
见 `plan/02` §二），启用时必须 exit 3 而绝不返回"零结果"。

## 模块②：失败优先三栏视图

**结构**（`tui/app.py`）：

```
Header
├─ 左栏  Tree（suite → class → test，节点标签带 [fail/total]）
└─ 右栏  Vertical
         ├─ summary（Static：total / fail / skip / flaky / broken / slow）
         ├─ failure 原文（Static）
         └─ sparkline（Sparkline：最近 N 次 run 的 pass=1 / fail=0，skip/missing 不绘制）
F/S/D 主区域（Static，#view-body：同屏切换，Esc 回三栏）
搜索框（Input，#search：默认隐藏且不可聚焦，`/` 才打开）
Footer（键位栏，数据源 = keys.py）
```

**实现要点**：

- `queries.py` 只读 SQL：`tree_rows(run_id)`、`summary(run_id)`、`case_detail(run_id, case_id)`、
  `history(case_id, window)`。返回纯 dataclass / dict，**不返回 Textual 对象**。
  M3 另加三个视图的**取数**（只取原始数据，不做判定）：`matrix_rows(run_id, window)`
  返回 `(run 列, 状态行)`、`slow_rows(run_id)`（`time_ms IS NULL` 的行不进表）、
  `diff_rows(run_before, run_after)`（原始状态对，任一侧缺行记 `None`）。
- `app.py` 只做装配与事件；大库查询走 `@work(thread=True)` + `post_message`，UI 不阻塞
  （线程里每次自开一条**已存在的**连接：sqlite 连接不跨线程复用）。
- **失败优先排序**：同一父节点下，`fail_count > 0` 的子树在前；同组内 suite 按 XML 出现序
  （`suites.suite_id` 升序），class/name 按字典序。排序函数单点在 `queries.fail_first_key`，
  树、矩阵、瀑布共用（K35）。
- 键位全部来自 `keys.py`：`j/k/g/G/Enter/F/S/D//e/?` + `Esc`/`q`；Footer 与帮助层从
  `keys.KEYS` 生成。任何地方另写键位字面量 = 缺陷（`tests/test_keys_single_source.py` 用 AST 扫描）。
- **TUI 默认不聚焦任何控件**：`Input.can_focus = False`，`on_ready` 里 `set_focus(None)`；
  按 `/` 时才临时打开搜索框。否则 Textual 会把首焦点给搜索框，`j`/`F` 全被它吃掉（K42）。
- `F`/`S`/`D` 是**同屏切换的主区域**，不是新窗口；切回 `Esc`/`q` 回到三栏。三者各自
  渲染真实查询结果（死壳判据：只画标题不接查询即视为未交付）。
- **M3 的交付线是"接真实查询的骨架"**：`F` 只摆四态矩阵（不做 `flaky_score` 与四类分型）、
  `S` 只摆本 run 的耗时降序与比例条（不算 p50/p95、不判回归）、`D` 只摆 `before→after`
  原始状态对（不做三类分类）。三者的**口径**留给 M4/M5——在 M3 顺手算一份就是把口径复制成第二套。
- **M4 已把三者的判定接上**：`F` 的行序改 `flaky_score` 降序、每行带 `flaky.py` 的分型标签；
  summary 的 `flaky` / `broken` 由 `flaky.py` 填；`D` 改为 `diff.py` 的三类分组渲染。
- **M5 把 `S` 的判定也接上**：`S` 每条用例带 `slow.py` 的 `p50` / `p95` / 回归判定
  （`reg=yes/no/?`，`?` = 判不了）与按 `slow.bar_width`（整数运算）画的瀑布条；summary 的 `slow` 由
  `slow.py` 按"本 run 达到 `slow_ms` 的用例数"填（`queries.slow_summary_count`）。

- `report_model.build_report` 是 TUI 与导出的**共用模型**（`app.py` 必须 import 它，
  `cli.REQUIRED_IMPORTS` + `tests/test_layering.py` 钉住）：summary 的字段与键序取自
  `view.summary_fields`；`flaky`/`broken`/`slow` 在各自里程碑前恒为 `None`（K37），
  **M5 起三者全部有值**（`flaky`/`broken` 由 `flaky.py`、`slow` 由 `slow.py` 填）。
  `build_report` 还产出 `profiles`（分型）/ `slow` + `regressions`（回归清单）/ `diff`（三类分类）——
  导出与 `--fail-on` 门禁都只读这一份模型。

**降级**：终端宽度 < 80 列（门槛取 `rules/view.json` 的 `min_width_single_column`，
判据是 `<`）→ 单栏模式（只显示树，右侧改为按 `Enter` 进入的详情页）；
`NO_COLOR`（**按有没有设置判**，不看取值）/ `TERM=dumb` / 非 tty / 无真彩色 → 保留结构，
颜色退化。两条都由 `view.py` 的**纯函数**决定（`column_mode` / `style_mode`），
`app.py` 只把结果落到 CSS 类上——所以两条都有不依赖 Pilot 的测试，且"彩色"与"退化"
渲染出的文本**剥掉标记后逐字符相同**（K39/K40）。

## 模块③：flaky 矩阵与分型

**实现**：`flaky.py`（纯函数，无 IO）。

```python
def classify(history, rules) -> CaseProfile
# history: [(run_seq, status), ...] 按 run_seq 升序，status ∈ {pass, fail, skip, missing}
```

- 分母只含 `pass` / `fail`；`skip` / `missing` 既不进 `fail_rate` 分母，也**不制造 transition**。
- `transitions` 只在**相邻两个参与计数的 run**（都属 pass/fail）且状态不同时 +1；
  中间的 skip/missing 被跳过，不视为"状态变化"。
- `n` = 参与计数的次数（pass+fail 计数）；`flaky_score = transitions / (n - 1)`，`n < 2` → `0`。
- 分型顺序（**先判恒失败**）：`fail_rate == 1` → `broken`；`fail_rate == 0` → `stable`；
  `0.05 <= fail_rate <= 0.95` 且 `transitions >= 3` → `flaky`；其余 → `watch`。
- 阈值、窗口、`watch` 兜底全部从 `rules/flaky.json` 读；代码里**不得出现阈值字面量**
  （`tests/test_no_rule_literals.py` 扫描 `flaky.py` / `slow.py` / `report_model.py` 的数值常量）。
- **零计数样本（K34）**：`n == 0`（全 skip/missing）时 `fail_rate` 是 0/0、**无定义**
  （`model.mean_fraction` 返回 `None`，不是 `Fraction(0)`）→ 一律 `watch`。
  "一次都没真正跑过"不构成"稳定"证据。
- **`broken ∩ flaky == ∅` 用独立断言**（不靠上面的分型顺序自证）：`tests/test_flaky.py`
  与 `bench/bench_flaky.py` 各拿一份固定 fixture 的 broken / flaky 两份集合**求交**。

**矩阵渲染**：test × run，单元格四态字符 `·`（pass）/ `✗`（fail）/ `-`（skip）/ `?`（missing）；
每行另带分型标签与 `flaky_score`（来自 `flaky.classify`）。行按 `flaky_score` 降序，
同分按 `(suite_name, classname, name)` 字典序。**行序与分型都取自 `flaky.py`**——
`queries.matrix_rows` 只把结果摆进矩阵，不复制判定。

**summary 接分型**：`queries.summary` 的 `flaky` / `broken` 由 `flaky.py` 对**本 run 的
每条用例**按窗口历史分型后计数（`queries.profile_summary_counts`）；窗口与矩阵同取
`view.sparkline_runs`，所以"summary 里的 flaky 数"与"矩阵里标 flaky 的行数"是同一份判定。

**降级**：窗口内 run 数 < `min_runs_for_flaky`（=2）→ 分型一律 `watch`（**不得输出 flaky**）。

## 模块③b：两次 run 的用例级 diff（`D` 视图）

**实现**：`diff.py`（判定层纯函数，不 import 规则包——diff 三类完全由**状态对**决定，
没有阈值可调，因此不含任何数值常量）。

```python
def classify(status_before, status_after) -> str   # CLASS_ORDER 之一
def classify_rows(rows) -> [ClassifiedDiff]         # 给每条 DiffRow 打分类
def group_rows(classified) -> {kind: [...]}         # 按 CLASS_ORDER 分桶
```

| 类 | 条件 | 含义 |
| --- | --- | --- |
| `new-failures` | `after == fail` 且 `before != fail` | 这次新坏的（含 base 缺行） |
| `fixed` | `before == fail` 且 `after == pass` | 上次坏、这次**跑过且过了** |
| `still-failing` | `before == fail` 且 `after == fail` | 一直坏 |
| `unchanged` | 其余组合 | 不在上面三类里的一切 |

- **`fixed` 要求 `after == pass`**：`fail→skip` / `fail→缺` 落 `unchanged`，**不是**修复——
  没有 `pass` 就没有"修好了"的证据。把"这次没跑/被跳过"算成修复会让修复数虚高
  （正是 `--fail-on new-failures` 想抓的自欺）。
- **缺行（`None`）不等于任何状态**（K24/K28 同一条纪律）：`缺→fail` 是 `new-failures`，
  `fail→缺` 落 `unchanged`。
- `CLASS_ORDER` 是**展示与对账的固定顺序**（新增失败在前）；`RECONCILED_CLASSES` 是
  `tests/test_diff.py` 逐类断言的三个对象。

## 模块④：慢测试与回归

**实现**：`slow.py`（纯函数，**M5 落地**）。

- `percentile(values, p)`：线性插值，索引 `(n-1)*p`，`lo=floor`、`hi=ceil`，
  `lo==hi` 取该值，否则 `v[lo] + (v[hi]-v[lo])*(idx-lo)`。输入按值升序排序（稳定）。
- 缺失 run 的耗时**不补 0**、不进样本（记 `missing`）。
- `regression(base_p50, curr_p50, rules)`：`curr/base >= ratio` **且** `curr-base >= delta_ms`，
  边界值计入（`>=`）。`base_p50 == 0` → 不判回归，标 `undefined_base`。
- 瀑布条宽度 = `round(time_ms / max_time_ms * width)`（整数运算，避免浮点抖动）；
  `max_time_ms == 0` → 全宽 0。

- 瀑布条宽度 = `slow.bar_width(time_ms, max_time_ms, width)`：**整数运算**做四舍五入
  （余数加倍与除数比较），不走浮点除法、也不用 `round()`（银行家舍入在 `.5` 边界给出
  与"四舍五入"不同的答案）；`max_time_ms == 0` → 全宽 0。

**降级**：总样本 `0` 或回归窗口任一侧无样本 → `insufficient_history`（回归判定落
`missing_window`）；总样本恰 1 → `single_sample`（p50 == p95 == 该值，比不出趋势）。
**"不可判"返回 `None` 而不是 `False`**——`False` 是"判过了、没回归"，`None` 是"判不了"；
混同会让 CI 门禁在样本不足时静默放行。

## 模块⑤：导出与 CI 门禁

**实现**：`report_model.py` 定义 `REPORT_FIELDS`（有序元组），
`build_report(conn, run_id, window)` 返回纯 dict；`render_md(report)` 与
`render_json(report)` 都只消费它（M5 落地）。TUI 的 summary/矩阵也从同一模型取值。

- JSON：`json.dumps(..., ensure_ascii=False, sort_keys=False, indent=2)` + 末尾换行；
  **键序 = 字段声明序**（不排序，避免"声明序"与"输出序"两套）。
- md：列顺序 = 字段声明序；表格用 `|` 分隔，单元格内的 `|` 与换行转义（`\|`、`<br>`）。
- **不写生成时刻**；不含 `ingested_at`、绝对路径（只写 `source_path` 的相对形式）。
- 两次导出逐字节一致（`tests/test_export_determinism.py` 双跑 `cmp`；`bench/bench_export.py`
  的 `export/byte_identical` 给一份可复跑的总账）。
- 导出面是**纯函数**（消费一个 dict），所以 `bench_export.py` 用确定性合成模型对账，
  不碰 SQLite。

**`--fail-on` 语义**：

| 值 | 命中条件 | 退出码 |
| --- | --- | --- |
| `flaky` | 分型 `flaky` 的用例数 > 0 | 1 |
| `new-failures` | 相对 base run 新增的 `fail` 用例数 > 0 | 1 |
| `regressions` | 回归清单非空 | 1 |
| 未命中 | — | 0 |
| 未知值 / 缺参数 | argparse `choices` | 2 |
| 库不存在 / 不可读 / 无 run | — | 3 |

`--fail-on` 的判定只读模型，不重新查库（保证"看到的就是门禁算的"）。

**降级**：库文件不存在 → exit 3 并在 stderr 点名路径与"先跑 `testdeck ingest`"；
库存在但无 run → exit 3（不是 0：空库不等于"没有失败"）。
`--fail-on` 未命中 → 0；命中 → 1 并在 stderr 写出命中原因（`flaky=N` / `new-failures=N` /
`regressions=N`）。

## 编排与数据流

```
paths/globs ──discover──▶ files ──parse_file(iterparse)──▶ ParsedRun
                                                             │
                        db.ingest_run(upsert) ◀──────────────┘
                                 │
                        SQLite（runs/suites/cases/occurrences）
                                 │
              ┌──────────────────┴──────────────────┐
        queries.py（只读）                     queries.py（只读）
              │  └─ 调 flaky / diff / slow（判定层）
              │                                     │
        tui/app.py（三栏 + F/S/D）          report_model.build_report → md / json
                                              └─ gate_hits(--fail-on) → exit code
```

**失败路径零副作用**：`ingest --dry-run`、`export` 失败、`selftest` 失败三种情形，
命令前后全仓快照差集必须为空（`tests/test_failure_no_side_effects.py`）。
