## 三、每个里程碑的收尾流程（固定顺序，不跳步）

1. DoD 逐项验证（命令 + 输出落 `plan/HANDOFF-M<next>.md` §1）。
2. 回写状态：`plan/00` 台账行 + 里程碑表、本文件状态表、`plan/06` 缺口表、`README.md` 状态表。
3. 写 `plan/HANDOFF-M<next>.md`（六节：当前进度+证据 / 待办 / 既定口径 K 编号 / 本机环境坑 /
   DoD checklist / 命令速查）。
4. 跑布局门（必须绿）+ 全量 `pytest`。
5. commit；有远端则 push 并等 CI（无远端时写"本地等价校验（CI 待首推验证）"）。

**收尾棒（M6）也必须写 `HANDOFF-M6.md`**——实测最常见的漏写就在这里。

## 四、发布流程（M6）

1. **干净环境验证**：`git clone --no-local` → 新 venv → 按 README 逐条跑 → 逐条记退出码与语义。
2. **脱敏四步**：源码常量 / 文档 / 产物 / 提交元数据（作者与 tagger 邮箱）各扫一遍；
   本仓白名单只有 `yuluo554@users.noreply.github.com` 形态。
3. **建仓与首推**：`gh repo create yuluo554/testdeck --public` → push main → 等 CI 绿。
4. **tag + Release**：annotated tag `v0.1.0`；附件口径 = **手工源码包**（`python -m build --sdist`），
   sha256 只写进 Release 正文（写进包内文档会立刻失效）。
5. **发布留档** `plan/RELEASE-M6.md`：§一 tag 前事实 / §二 tag 后追加事实 / §三 阶段 7 覆盖对账表
   （逐条：实现 / 不适用+理由 / 待首推）。
6. **发布物本体复核**：真下载到中立目录 → `sha256sum -c` → 解包树 vs `git archive <tag>` 解包树
   `diff -r` → 在解包目录之外装并跑 `testdeck selftest`。
